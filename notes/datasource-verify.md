## 三、三个关键实现发现

### 1. zzshare 财报是**单季度值**，必须累加 ⚠️

```
2024Q4 单季营收  266.60 亿
四季累加         1153.93 亿  ← ≈ 年报
不累加直接用     266.60 亿  ← 错 4 倍
```

已在 `zzshare_adapter._accumulate_annual()` 实现（利润表/现金流/指标累加，资产负债表取期末）。

### 2. 单位与 Tushare 不同 ⚠️

| 数据 | zzshare 单位 | schema 标准 |
|---|---|---|
| 财报数值 | **元** | 元 |
| 估值-市值 | **亿元** | 元（适配器 ×1e8） |
| 估值-股本 | **万股** | 股（适配器 ×1e4） |

已在适配器层做转换，schema 统一标"元"。

### 3. 接口是 `finance_stock(table=, code=, ...)`，不是按报告期

```
❌ 我最初写的：api.finance_income("2024-12-31")   # 返回全市场 5120 行
✅ 实际正确：  api.finance_stock(table="income", code="600887.SH",
                                start_date=..., end_date=...)  # 单股历史
```

## 四、致命限制

| 限制 | 影响 |
|---|---|
| **字段覆盖不全** | 应收账款、合同负债、资本开支、已付股息等**核心字段返回 None** |
| **无港股/美股** | 只支持 A 股 |
| 个人项目 | 长期稳定性未验证 |

### 对龟龟框架的影响

穿透回报率的 11 步计算**依赖大量现金流量表字段**：

```
步骤3  真实现金收入还原  → 需要 应收账款 ✗ 预收款 ✗
步骤5  经营性现金支出    → 需要 供应商支付 ✗ 员工现金 ✗
步骤6  资本开支扣除      → 需要 资本开支 ✗
步骤10 分配意愿          → 需要 已付股息 ✗
```

**结论：zzshare 不足以独立支撑龟龟框架**，只能作为**利润表 + 估值 + OCF 的补充源**。

## 实现要点

**双后端互补**：
```
新浪源 (stock_financial_report_sina)
  → 三大报表 / 中文列名 / 累计口径
东财源 (stock_cash_flow_sheet_by_report_em)
  → 现金流量表 / 英文列名 / 含补充资料(D&A、资本开支、已付股息)
```

已实现 `field_overrides()` 机制：基础类根据实际返回行动态切换映射（东财英文列 vs 新浪中文列）。

AkShare **能支撑 11 步穿透回报率**（关键字段全部可取得）：

| 步骤 | 所需字段 | AkShare |

**结论：A 股可以完全摆脱 Tushare 付费**，改用 AkShare。

## 唯一遗留风险

AkShare 是**爬虫集合**，接口会随上游（新浪/东财）改版而失效。
建议：保留 `datasource` 分层，配 `zzshare` 作降级，并定期回归测试。
