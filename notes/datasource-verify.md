## 三、三个关键实现发现

### 1. zzshare 财报是**单季度值**，必须累加 ⚠️

```
2024Q4 单季营收  266.60 亿
四季累加         1153.93 亿  ← ≈ 年报
不累加直接用     266.60 亿  ← 错 4 倍
```

已在 `zzshare_adapter._accumulate_annual()` 实现（利润表/现金流/指标累加，资产负债表取期末）。

### 2. 单位与 Tushare 不同 ⚠️

| 数据 | zzshare 单位 | schema 标准 |
|---|---|---|
| 财报数值 | **元** | 元 |
| 估值-市值 | **亿元** | 元（适配器 ×1e8） |
| 估值-股本 | **万股** | 股（适配器 ×1e4） |

已在适配器层做转换，schema 统一标"元"。

### 3. 接口是 `finance_stock(table=, code=, ...)`，不是按报告期

```
❌ 我最初写的：api.finance_income("2024-12-31")   # 返回全市场 5120 行
✅ 实际正确：  api.finance_stock(table="income", code="600887.SH",
                                start_date=..., end_date=...)  # 单股历史
```

## 四、致命限制

| 限制 | 影响 |
|---|---|
| **字段覆盖不全** | 应收账款、合同负债、资本开支、已付股息等**核心字段返回 None** |
| **无港股/美股** | 只支持 A 股 |
| 个人项目 | 长期稳定性未验证 |

### 对龟龟框架的影响

穿透回报率的 11 步计算**依赖大量现金流量表字段**：

```
步骤3  真实现金收入还原  → 需要 应收账款 ✗ 预收款 ✗
步骤5  经营性现金支出    → 需要 供应商支付 ✗ 员工现金 ✗
步骤6  资本开支扣除      → 需要 资本开支 ✗
步骤10 分配意愿          → 需要 已付股息 ✗
```

**结论：zzshare 不足以独立支撑龟龟框架**，只能作为**利润表 + 估值 + OCF 的补充源**。

## 五、更新后的选型结论

| 源 | 定位 | 依据 |
|---|---|---|
| **Tushare** | **主力（仍必需）** | 唯一字段完整的三表源 |
| zzshare | 交叉验证 + 利润表兜底 | 利润表准确、有 OCF、免 token |
| AkShare | 待实测（下一步） | 字段名需逐项核对 |

**建议**：保留 `datasource` 分层，但**短期内 Tushare 仍是主力**——zzshare 的价值在于**多源交叉验证**（已实现 `compare()`）和**无 token 时的降级可用**。
